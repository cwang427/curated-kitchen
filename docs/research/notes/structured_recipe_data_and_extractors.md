# Structured recipe data in HTML and deterministic extractors (state as of 2026-09-28)

Method note for the report writer: besides docs/blogs, I pulled 48 saved page snapshots from the `hhursev/recipe-scrapers` test corpus (`tests/test_data/<host>/*.testhtml`, main branch as of 2026-09-28) and parsed their `<script type="application/ld+json">` blocks locally. These are real publisher pages, but capture dates are not recorded in the filenames (the corpus spans roughly 2021-2025), so treat per-site shapes as "observed at capture time", not guaranteed-current. Live fetching of publisher pages and webdatacommons.org was blocked by the research proxy (noted in Gaps).

## KQ1. schema.org/Recipe: which properties matter, how it is embedded, and how widely it is adopted

### Takeaway
Google's Recipe rich-result contract (required `name` + `image`; recommended `recipeIngredient`, `recipeInstructions` as `HowToStep`/`HowToSection`, `recipeYield`, ISO-8601 `prepTime`/`cookTime`/`totalTime`, `author`, `description`, `keywords`, `nutrition`, `video`, `aggregateRating`, `recipeCategory`/`recipeCuisine`, `datePublished`) is what publishers actually emit, overwhelmingly as JSON-LD; measured corpora show Recipe is a top-10 schema.org class and that JSON-LD overtook Microdata site-wide in 2020, but no Recipe-specific domain count could be retrieved.

### Cited Findings
- Google's Recipe structured-data guide lists `name` ("The name of the dish") and `image` ("Image of the completed dish") as the only required properties; `image` should be "multiple high-resolution images (minimum of 50K pixels when multiplying width and height) with the following aspect ratios: 16x9, 4x3, and 1x1", given as an array of URL strings `["https://example.com/photos/1x1/photo.jpg", ".../4x3/photo.jpg", ".../16x9/photo.jpg"]` (URL or ImageObject both accepted). — [Google Search Central: Recipe](https://developers.google.com/search/docs/appearance/structured-data/recipe)
- Recommended properties per Google: `recipeIngredient` (Text array; "Include only the ingredient text that is necessary for making the recipe"), `recipeInstructions` (HowToStep, HowToSection, or Text; "We recommend using HowToStep"; "don't include other text such as 'Directions', 'Watch the video', 'Step 1'"), `recipeYield` (Text or Integer; example `"recipeYield": ["6", "24 cookies"]`; required "if you specify any nutritional information per serving"), `prepTime`/`cookTime` (ISO 8601 Duration; "Always use in combination with" each other), `totalTime` ("Use totalTime or a combination of both cookTime and prepTime"), `author` (Person or Organization), `description`, `keywords` (comma-separated; "Don't use a tag that's actually a recipeCategory or recipeCuisine"), `nutrition.calories` (needs `recipeYield` servings), `video` (VideoObject), `aggregateRating`, `recipeCategory`, `recipeCuisine`, `datePublished` (ISO 8601). — [Google Search Central: Recipe](https://developers.google.com/search/docs/appearance/structured-data/recipe)
- `HowToStep` properties per Google: `text` (full instruction text), `name` (short phrase), `url` (anchor link to the step), `image`. Example: `{"@type":"HowToStep","name":"Preheat","text":"Heat oven to 425°F.","url":"https://example.com/recipe#step1","image":"https://example.com/photos/recipe/step1.jpg"}`. `HowToSection` = `{"@type":"HowToSection","name":"Assemble the pie","itemListElement":[{"@type":"HowToStep","text":"..."}]}`. — [Google Search Central: Recipe](https://developers.google.com/search/docs/appearance/structured-data/recipe)
- Google: for multiple recipes on one page "Use multiple separate Recipe objects, not HowToSection"; a carousel is an `ItemList` of `ListItem{position,url}` and "Your site must have a summary page that lists all the recipes in the collection". — [Google Search Central: Recipe](https://developers.google.com/search/docs/appearance/structured-data/recipe)
- schema.org (displayed version V30.1, dated 2026-09-16) types: `recipeIngredient` (Text; supersedes the old `ingredients` property), `recipeInstructions` (CreativeWork, ItemList, or Text), `recipeYield` (QuantitativeValue or Text), `cookTime`/`prepTime`/`totalTime` (Duration), `cookingMethod`, `recipeCategory`, `recipeCuisine`, `nutrition` (NutritionInformation), `suitableForDiet` (RestrictedDiet); inherited from HowTo: `supply`, `tool`, `step`, `yield`, `estimatedCost`; from CreativeWork: `author`, `datePublished`, `image`, `aggregateRating`, `keywords`, `description`, `video`. — [schema.org/Recipe](https://schema.org/Recipe)
- Real pages embed in three ways observed in the fixture corpus: (a) a single top-level Recipe object; (b) a top-level JSON array whose first element is the Recipe with `"@type": ["Recipe"]` (Dotdash Meredith sites: Serious Eats, Simply Recipes, Martha Stewart, EatingWell); (c) a Yoast/Rank Math `@graph` array in which the Recipe is one node among `['Article','WebPage','ImageObject','BreadcrumbList','WebSite','Organization','Person','Recipe']` (Budget Bytes, and every WPRM/Tasty Recipes blog sampled). — [budgetbytes fixture](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/budgetbytes.com/budgetbytes.testhtml); [seriouseats fixture](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/seriouseats.com/seriouseats.testhtml)
- Microdata-only still exists: the Epicurious fixture has zero `ld+json` blocks and uses `itemtype="https://schema.org/Recipe"` with `itemprop` values including the superseded `ingredients` (not `recipeIngredient`), plus `recipeInstructions`, `recipeYield`, `recipeCategory`, `recipeCuisine`, `aggregateRating`, `image`, `author`. — [epicurious fixture](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/epicurious.com/epicurious.testhtml)
- ISWC 2023 study of the October 2021 Web Data Commons JSON-LD corpus (82 billion quads, 6.7 billion schema.org entities, 35 million websites): Recipe is among the top-10 most used classes; entities average 14.08 of 144 defined properties ("AvP"); Recipe's property coverage metric is 0.72; the top-10 Recipe properties by usage are name, image, datePublished, description, author, totalTime, recipeYield, recipeIngredient, recipeInstructions, keywords; the study covers JSON-LD only because it is "the most used format". — [Schema.org: How is It Used? (ISWC 2023)](https://ceur-ws.org/Vol-3632/ISWC2023_paper_445.pdf)
- WDC series paper: PLDs with schema.org grew from 400,000 (3.1% of Common Crawl sites, 2013) to 12.8 million (37.9%, 2022); "since 2020, more PLDs use the JSON-LD syntax than Microdata"; "webmasters primarily use the JSON-LD and Microdata formats". — [Brinkmann et al., WWW 2023](https://www.uni-mannheim.de/media/Einrichtungen/dws/Files_Research/Web-based_Systems/pub/Brinkmann-etal-TheWDCSchemaorgDataSetSeries-WWW2023.pdf)
- WDC October 2023 release: 3.35 billion pages from 34.1 million websites; 15 million PLDs contain structured data; ~9.5 million websites use JSON-LD, 7.4 million Microdata, ~0.5 million RDFa (no Recipe-specific figure given). — [WDC 2023 release announcement, W3C list](https://lists.w3.org/Archives/Public/public-schemaorg/2024Feb/0001.html)

### Inferences
- A deterministic extractor should accept the union of Google's shapes and schema.org's looser typings: every polymorphic field (`image`, `recipeYield`, `recipeInstructions`, `author`, `keywords`) must be normalized by type-switch, not by assuming Google's example form.
- Because Google's guide is what plugin authors target, `HowToStep`/`HowToSection` with `name`/`text`/`url` is the de-facto instruction encoding on WordPress; string-only instructions are a publisher-CMS pattern (see KQ2).
- Microdata support is still needed for the long tail (Epicurious-style pages) but can be a second pass; JSON-LD first is the correct priority given 2020+ adoption data.

### Gaps
- No Recipe-class domain count could be retrieved: webdatacommons.org was unreachable through the research proxy (CONNECT 403 / robots failure), and neither WDC paper nor the 2023 announcement breaks out Recipe.
- Google's page as fetched did not state explicitly that Microdata/RDFa are accepted for Recipe (only JSON-LD examples were visible), so that support claim rests on the general structured-data docs, not this page.

## KQ2. What markup the dominant WordPress plugins and large publishers emit, and which are missing/malformed/paywalled

### Takeaway
WordPress plugins (WP Recipe Maker, Tasty Recipes, Create) emit Google-shaped JSON-LD, usually merged into a Yoast/Rank Math `@graph` where `author` is only an `@id` reference; large publishers each have idiosyncrasies (Dotdash's top-level array with `@type` arrays, Hearst's `HowToSection` + `PT0S`, King Arthur's HTML inside JSON strings, Jamie Oliver's single-string instructions, Food Network UK omitting `recipeInstructions` entirely, Epicurious microdata-only, NYT's `isAccessibleForFree:"False"` paywall flags).

### Inferences
- The WordPress majority produces the most parser-friendly data (HowToStep with anchors, dual-form yield, 4-size image arrays, unit-tagged nutrition), but always requires `@graph` traversal and `@id` dereferencing for `author`.
- Publisher CMSs are where deterministic extraction breaks: missing instructions (Food Network UK), HTML-in-strings (King Arthur), single-string instructions (Jamie Oliver), empty arrays and `PT0S` placeholders (Hearst). These are exactly the cases where an LLM normalizer earns its keep, but only after the JSON-LD has been read.
- Paywall flags (`isAccessibleForFree` as string "False" or boolean, `hasPart.cssSelector`) are worth surfacing as a signal, but the NYT fixture shows the JSON-LD can still be complete even when the visible DOM is truncated.

### Gaps
- Cooked and Zip Recipes plugin markup were not researched (no time/budget); Create's exact JSON-LD shape was not observed in any fixture (I could not confirm any sampled site used Create; the `mv-create` string on WPRM pages is likely Mediavine ad code, so I did not count it).
- Live current-markup verification for Allrecipes and NYT was impossible (proxy blocked publisher fetches; no Allrecipes fixture was found under the guessed filenames).

## KQ3. Common JSON-LD gotchas (shapes an extractor must handle)

### Takeaway
Real-world Recipe JSON-LD is polymorphic on nearly every field; the observed variants below (with the normalization code that mature libraries use) are the checklist for a deterministic parser.

### Cited Findings
- Where the Recipe lives: top-level object; top-level array; `@graph` array (Yoast/Rank Math); `WebPage.mainEntity`. recipe-scrapers' finder checks `_find_entity(item, "Recipe")`, then `WebPage` + `mainEntity`, then iterates `item.get("@graph", [])`, with `@type` compared case-insensitively as string or list. — [recipe-scrapers `_schemaorg.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_schemaorg.py). A Kinboard importer bug: it "only examined the top-level object's `@type`", so Yoast/Rank Math pages (example loveandlemons.com) with `{"@context":..., "@graph":[{"@type":"Article"...},{"@type":"Recipe"...}]}` were never detected; fix = search `@graph` entries and accept `@type` as string or array. — [kinboard issue #283](https://github.com/svenger87/kinboard/issues/283). Raymond Camden: "I've seen this be an array, and just a json string with a top level @graph"; checks `@type` with `.indexOf()` because it is "not sure if ALWAYS an array". — [raymondcamden.com](https://www.raymondcamden.com/2024/06/12/scraping-recipes-using-nodejs-pipedream-and-json-ld)
- Multiple `ld+json` blocks per page are normal (BBC GF 3, tasty.co 3, Food Network UK 3 with the Recipe in the third; Well Plated 2). — [foodnetwork fixture](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/foodnetwork.co.uk/foodnetwork.testhtml); [tasty_1](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/tasty.co/tasty_1.testhtml). MealPlan's extractor spec: "Parse every `<script type="application/ld+json">` block, not just the first"; "If several Recipe objects exist, score/select the most complete candidate"; "Tolerate both schema.org HTTP/HTTPS forms"; also recursively search Next.js `__NEXT_DATA__` for "recipe-shaped objects"; return "a candidate plus provenance and evidence, e.g. `jsonLD`, `microdata`, `embeddedJSON`". — [MealPlan issue #20](https://github.com/holgerkrupp/MealPlan/issues/20)
- `@type` casing/arrays: `["Recipe"]`, `["Recipe","NewsArticle"]` (Dotdash), `nutrition.@type = "nutritionInformation"` (Tasty Recipes), custom `"ExtendedRecipe"`. — [eatingwell](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/eatingwell.com/eatingwell.testhtml); [cookieandkate_2](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/cookieandkate.com/cookieandkate_2.testhtml); [wellplated_2](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/wellplated.com/wellplated_2.testhtml)
- `recipeInstructions` variants observed: single plain string (Jamie Oliver); single HTML string (King Arthur); `[HowToStep{text}]`; `[HowToStep{name,text,url}]` with `name == text` (WPRM); `[HowToStep{text,url}]` (Tasty); `[HowToStep{image,text}]` (Dotdash); `[HowToStep{@context,text}]` (NYT); `[HowToSection{name,itemListElement:[HowToStep]}]` (WPRM groups, Hearst); `[[HowToStep...]]` nested list (Food52); `[]` (Pioneer Woman). recipe-scrapers handles "string, HowToStep (with name/text deduplication), HowToSection (with itemListElement normalization from dict to list)" and drops `name` when it is a prefix of `text`; Tandoor's `parse_instructions()` flattens "lists of strings, objects with 'text' keys, and nested itemListElement arrays". — [`_schemaorg.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_schemaorg.py); [Tandoor `recipe_url_import.py`](https://raw.githubusercontent.com/TandoorRecipes/recipes/develop/cookbook/helper/recipe_url_import.py); fixtures cited in KQ2. An early Mealie issue (#73, "Scraper not working with recipe containing HowToSection") documents this failure mode historically. — [Mealie issue #73](https://github.com/hay-kot/mealie/issues/73)
- `image` variants: string; array of strings (WPRM 4 crops; BA 8); `ImageObject{url,width,height}`; `[ImageObject]`; `ImageObject{url}` only. recipe-scrapers: `if isinstance(image, list): image = image[0]; if isinstance(image, dict): image = image.get("url")`, then requires an `http(s)` scheme; Tandoor's `parse_image()` does the same and "rejects relative paths"; recipe-scrapers falls back to OpenGraph `og:image` (an `OpenGraph` object is built from the soup alongside the schema). — [`_schemaorg.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_schemaorg.py); [`_abstract.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_abstract.py); [Tandoor importer](https://raw.githubusercontent.com/TandoorRecipes/recipes/develop/cookbook/helper/recipe_url_import.py)
- `recipeYield` variants: integer `2`/`4`/`8`; `"8"`; `["6"]`; `["4","4 burgers"]`, `["20","2 pies"]`; free text `"Makes 12"`, `"Serves 2 to 4"`, `"4 servings "`, `"8 - 10 serving(s)"`, `"4-5"`, `"22 cookies"`, `"5 cups (about 120 to 160 crackers)"`. recipe-scrapers `get_yields()`: for lists, picks the element containing a unit pattern; ranges via `r"\d+(\s+to\s+|-)\d+"` taking the rightmost value; number via `r"(\D*(?P<items>\d+(\.\d*)?)?\D*)"`; unit detection via singular/plural word lists (e.g. "cookie"/"cookies", "kg", "lbs", "ml"); if a unit word is found it returns e.g. "4 dozen", else checks for "makes"/"porzioni", else defaults to "servings". Tandoor's `parse_servings()` just regexes `\d+` and defaults to 1. — [`_utils.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_utils.py); [Tandoor importer](https://raw.githubusercontent.com/TandoorRecipes/recipes/develop/cookbook/helper/recipe_url_import.py)
- Durations: mostly ISO 8601 (`PT10M`, `PT1H`, `PT140M`, `PT24H0M`, `PT1M33S`), but `PT0S` placeholders (Hearst) and sites with no time fields at all (BA). recipe-scrapers `get_minutes()`: if the string starts with "P" and contains "T" it uses `isodate.parse_duration()` and rounds up to minutes; otherwise a natural-language regex `(?:\D*(?P<days>\d+)\s*(?:days|D))?(?:\D*(?P<hours>[\d.\s/?¼½¾⅓⅔⅕⅖⅗]+)\s*(?:hours|hrs|hr|h|óra|:))?(?:\D*(?P<minutes>\d+)\s*(?:minutes|mins|min|m|perc|$))?(?:\D*(?P<seconds>\d+)\s*(?:seconds|secs|sec|s))?`; ranges ("1-2 hours", "to") take the upper bound; unicode fractions in hours are handled; returns None when zero; a `QuantitativeValue` dict uses `maxValue`. — [`_utils.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_utils.py); [`_schemaorg.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_schemaorg.py)
- Ingredient strings: HTML entities (`&frac12;`, `&nbsp;`), inline `<a>` tags with `data-sku` (King Arthur), section headers mixed into the list (`"For the dressing:"`, `"FOR THE MARINADE"`), price annotations (`"($6.99)"`), WPRM note rendering as double parentheses `"1 ⅔ cups warm milk ((400 ml))"`, mixed unicode/ASCII fractions (`"1 ¼ cup"`, `"1 1/2 cups"`, `"1 and 1/3 cup (167g)"`), trailing spaces. recipe-scrapers `normalize_string()` repeatedly `html.unescape`s until stable, strips tags with `r"<[^>]*>"`, replaces nbsp/zero-width/tabs/newlines, removes the `((`/`))` pair "only if both present", and collapses whitespace; `recipeIngredient` is read as `recipeIngredient or ingredients`, nested lists are flattened with `chain(*ingredients)`, and `PropertyValue` objects are stringified from value/name/unitText. MealPlan spec: "Do not consider a heading/placeholder such as exactly `Ingredients`, `Zutaten`, `Directions`, `Instructions`". — [`_utils.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_utils.py); [`_schemaorg.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_schemaorg.py); [MealPlan issue #20](https://github.com/holgerkrupp/MealPlan/issues/20); fixtures in KQ2
- Ingredient sections are usually NOT in JSON-LD (only Simply Recipes/Jamie Oliver leak them as strings); recipe-scrapers reconstructs groups from the DOM: it selects heading + item elements (auto-trying WPRM/Tasty selectors when none given), walks them in DOM order, and fuzzy-matches each DOM item back to a schema ingredient string using unicode-fraction normalization plus a Dice-coefficient bigram similarity (`score_sentence_similarity`), returning `IngredientGroup(ingredients, purpose)` or a single ungrouped group. — [`_grouping_utils.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_grouping_utils.py)
- `author` variants: `{"@id": ...}` reference needing graph resolution (WPRM/Yoast), `Person`, `[Person]`, `[Person, Person]`, `Organization`; recipe-scrapers resolves `@id` against a `self.people` map and `aggregateRating` `@id`s against a ratings cache; Food Network needs `copyrightNotice`. — [`_schemaorg.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_schemaorg.py); [foodnetwork.py](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/foodnetwork.py)
- `keywords` as CSV string vs JSON array; `recipeCategory`/`recipeCuisine` as string vs array vs `[]`; recipe-scrapers converts lists to comma strings and applies `csv_to_tags()` (split, case-insensitive dedupe). — [`_schemaorg.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_schemaorg.py); [bonappetit fixture](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/bonappetit.com/bonappetit.testhtml)
- Nutrition units are inconsistent strings (`"516 kcal"`, `"334 calories"`, `"23 g"`) and sometimes non-schema keys; Google requires `recipeYield` whenever `nutrition.calories` is present. — [budgetbytes](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/budgetbytes.com/budgetbytes.testhtml); [cookieandkate_2](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/cookieandkate.com/cookieandkate_2.testhtml); [Google](https://developers.google.com/search/docs/appearance/structured-data/recipe)
- Thermomix-family sites embed private-use Unicode glyphs in step text (Tandoor maps `` to "reverse rotation"); Tandoor also converts `<strong>`/`<nobr>` in steps to Markdown `**`. — [Tandoor importer](https://raw.githubusercontent.com/TandoorRecipes/recipes/develop/cookbook/helper/recipe_url_import.py)
- A vendor guide claims "Most recipe apps handle flat HowToStep arrays well. Support for HowToSection groupings is less consistent", "Almost nobody uses suitableForDiet", and "only the largest publishers (Serious Eats, Allrecipes) consistently include VideoObject markup" — the corpus partly contradicts the last two (Tasty Recipes emits `suitableForDiet`; many WPRM blogs include `video`). — [flourpower.app guide (vendor)](https://flourpower.app/learn/json-ld-recipes); [cookieandkate_2](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/cookieandkate.com/cookieandkate_2.testhtml)

### Inferences
- A robust "find the Recipe" routine is: parse every ld+json block (tolerating leading/trailing junk and HTML-entity-encoded JSON), recurse through arrays/`@graph`/`mainEntity`/`itemListElement`, test `@type` case-insensitively as string-or-array, collect all candidates, and score by completeness (has ingredients + instructions) rather than taking the first.
- Normalization order that matches library behavior: unescape entities repeatedly, strip tags, collapse whitespace, then parse yields/durations; keep raw strings alongside normalized ones for LLM fallback.
- Ingredient-group recovery is inherently DOM-based (plugin class hooks + heading order), which is why it belongs in a DOM pass, not the JSON-LD pass.

### Gaps
- I did not find quantitative frequencies (what % of sites use string vs HowToStep instructions); only the 48-page sample above.
- Unit/quantity parsing of ingredient lines was only touched via library pointers (`parse-ingredient`, Tandoor's `ingredient_parser`); no accuracy benchmarks were found.

## KQ4. JavaScript/TypeScript libraries usable in a Cloudflare Worker

### Takeaway
There is now a maintained TypeScript port of recipe-scrapers (npm `recipe-scrapers`, v3.1.0 on 2026-09-23, cheerio + zod peers, 14 custom + 346 schema-only hosts), while the older npm recipe scrapers (`recipe-data-scraper`, `@dimfu/recipe-scraper`, `web-auto-extractor`, `microdata-node`) are Node-oriented (axios + cheerio) and mostly stale; for HTML parsing on Workers, `htmlparser2`, `node-html-parser` and `linkedom` (which explicitly supports Workers) are the pure-JS options, `HTMLRewriter` is native but streaming-only, and cheerio works but is CPU-heavy.

### Inferences
- For a Worker, the JSON-LD pass needs no DOM library at all: collect `<script type="application/ld+json">` text via `HTMLRewriter` text-chunk concatenation (or a regex over the buffered body) and `JSON.parse`; a DOM library is only needed for the microdata pass, OpenGraph, plugin-class fallbacks and Readability.
- The TS `recipe-scrapers` is the closest drop-in, but its `cheerio ^1` peer (which pulls `undici`/`parse5`) and `node >=22` engine declaration mean bundle size and Node-compat flags need checking on Workers; nobody has documented running it on Workers.
- `linkedom/worker` + `@mozilla/readability` is the documented-compatible route for a DOM on Workers; `node-html-parser` is the lightest pure-JS DOM-ish option.

- No source confirms the TS `recipe-scrapers` or cheerio 1.2 running on Cloudflare Workers under `nodejs_compat`; the only cheerio-on-Workers evidence is a 2018 thread.

## KQ5. Python reference ecosystem: how recipe-scrapers works and what it implies

### Takeaway
recipe-scrapers is schema.org-first (extruct JSON-LD + microdata) with hundreds of thin per-host classes that mostly patch what schema lacks (ingredient groups, odd authors, HTML-in-instructions); "wild mode" (`supported_only=False`) is the generic schema-only path, so the size of the site list measures the long tail of schema gaps, not the absence of schema.

### Cited Findings
- README: parses "standard HTML structure, Schema markup (including JSON-LD, Microdata, and RDFa formats) or OpenGraph metadata"; the package is "focused exclusively on HTML parsing" and users should "implement your own solution for fetching recipe HTMLs"; `scrape_html` is the entry point. — [GitHub hhursev/recipe-scrapers](https://github.com/hhursev/recipe-scrapers)
- `scrape_html(html, org_url, *, online=False, supported_only=None, ...)`: `host_name = get_host_name(org_url); if host_name in SCRAPERS: return SCRAPERS[host_name](...)`; otherwise with `supported_only=False` it builds `SchemaScraperFactory.generate(html=html, url=org_url, ...)` and returns it `if schema_scraper.schema.data`, else raises `NoSchemaFoundInWildMode(org_url)`; with `supported_only=True` an unknown host raises `WebsiteNotImplementedError`; `online=True` is deprecated ("Please use an HTTP client (such as 'requests' or 'httpx')"); the `SCRAPERS` dict supports alternate domains (`AlbertHeijn.host(domain="ah.be")`) and the module has on the order of 900+ scraper imports. — [`__init__.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/__init__.py)
- The docs' supported-sites page lists roughly 740+ site entries / 850-900 domains including regional variants; confirmed present: allrecipes.com, cooking.nytimes.com, bbcgoodfood.com, seriouseats.com, foodnetwork.com, kingarthurbaking.com, bonappetit.com, epicurious.com, food52.com, delish.com, tasty.co, simplyrecipes.com, thekitchn.com, budgetbytes.com, minimalistbaker.com, marthastewart.com, eatingwell.com, taste.com.au, jamieoliver.com, thewoksoflife.com, justonecookbook.com, hellofresh (regional), blueapron.com, cookpad.com; not listed: smittenkitchen, pinchofyum, cookieandkate (though a cookieandkate fixture exists in the repo), loveandlemons, halfbakedharvest (fixture exists). — [docs supported sites](https://docs.recipe-scrapers.com/getting-started/supported-sites/) (counts are the fetch tool's estimate; the page has no annotations)
- `AbstractScraper.__init__`: `self.soup = BeautifulSoup(self.page_data, "html.parser")`, `self.opengraph = ...(self.soup)`, `self.schema = ...(self.page_data)`; plugin wrappers (`SchemaOrgFillPlugin`, `OpenGraphFillPlugin`, `HTMLTagStripperPlugin`, `NormalizeStringPlugin`, `ExceptionHandlingPlugin`, ...) are applied per method when `plugin.should_run(host, name)`; `instructions_list()` = `instructions().split("\n")`; `ingredient_groups()` defaults to `group_ingredients(self.ingredients(), self.soup)`; `to_json()` walks public methods. — [`_abstract.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_abstract.py)
- `SchemaOrg` uses `extruct.extract(page_data, syntaxes=["json-ld","microdata"], errors=..., uniform=True)` (RDFa not in the syntax list despite the README wording). — [`_schemaorg.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_schemaorg.py)
- Site classes are thin: Allrecipes = host only; NYT/BBC GF = ingredient grouping selectors only; Food Network = author from `copyrightNotice`; King Arthur = split `<p>` in the instructions string. — [allrecipes.py](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/allrecipes.py); [nytimes.py](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/nytimes.py); [bbcgoodfood.py](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/bbcgoodfood.py); [foodnetwork.py](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/foodnetwork.py); [kingarthur.py](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/kingarthur.py)
- Mealie calls it as `scrape_html(recipe_html, org_url=self.url or "https://example.com", supported_only=False)`, returns None on `NoSchemaFoundInWildMode`/`AttributeError`, and only accepts a result that has instructions or ingredients. — [Mealie `scraper_strategies.py`](https://raw.githubusercontent.com/mealie-recipes/mealie/mealie-next/mealie/services/scraper/scraper_strategies.py)
- Tandoor wraps it in `get_from_scraper(scrape, request)`: `scrape.title()[:128]` or schema `name`; `description` > 256 chars is prepended to the first step; times from `prep_time()`/`cook_time()` else `prepTime`/`cookTime`, else `total_time()`, via `get_minutes`; keywords from `keywords`, `recipeCategory`, `recipeCuisine`, `author`; each ingredient string goes through `ingredient_parser.parse()` (amount/unit/food/note) with the raw text as `food` on failure; an empty step is appended if no instructions; a separate YouTube path uses `pytubefix`. — [Tandoor `recipe_url_import.py`](https://raw.githubusercontent.com/TandoorRecipes/recipes/develop/cookbook/helper/recipe_url_import.py)
- Mealie's last-resort `RecipeScraperOpenGraph` strategy reads `og:title`, `og:description`, `og:image`, `og:article:tag` via `extruct` and fills ingredients/instructions with the placeholder `"Could not detect ingredients"`. — [Mealie `scraper_strategies.py`](https://raw.githubusercontent.com/mealie-recipes/mealie/mealie-next/mealie/services/scraper/scraper_strategies.py)

### Inferences
- The per-host overrides are the empirical catalog of "what schema.org alone gets wrong": ingredient groups (almost universal), author encoding, HTML inside strings, missing instructions. A Worker port can reproduce most of the value with a generic DOM heading-walk plus plugin-class hooks rather than 900 host classes.
- The existence of `NoSchemaFoundInWildMode` as a first-class exception (and Mealie/Tandoor's downstream handling) shows that "no structured data at all" is a normal, expected outcome for the long tail; that is the natural LLM trigger point.

### Gaps
- The Python package's current `__version__` was not captured (the docs "how-to-use" page 404'd and the README fetch omitted it).
- extruct/trafilatura were not researched separately beyond their use inside recipe-scrapers/Mealie.

## KQ6. How established apps handle URL import

### Takeaway
Self-hosted apps (Mealie, Tandoor) run recipe-scrapers server-side with LLM/OpenGraph fallbacks; commercial apps split between server-side URL fetch (Samsung Food, Saffron, Crouton) and client-side clipping inside the user's own browser (Paprika's built-in browser, AnyList/Plan to Eat/Copy Me That extensions and share sheets, RecipeSage's in-page RecipeClipper), with manual highlight-to-field or copy/paste as the universal last resort.

### Cited Findings
- Mealie pipeline order: `RecipeScraperPackage` → `RecipeScraperOpenAI` → `RecipeScraperOpenAITranscription` → `RecipeScraperOpenGraph`. The OpenAI strategy only runs if `settings.ai_enabled`; it feeds the model page text (BeautifulSoup), the raw JSON-LD script content and an image URL (`og:image` or the largest `<img>` by dimensions) with the message `"Convert this content to JSON: {text}"`, then converts the model's JSON back into an ld+json HTML document (`ld_json_to_html()`) and re-runs the normal recipe-scrapers cleaner on it; the transcription strategy uses `yt_dlp` subtitles/audio for video URLs. — [Mealie `scraper_strategies.py`](https://raw.githubusercontent.com/mealie-recipes/mealie/mealie-next/mealie/services/scraper/scraper_strategies.py)
- Mealie docs: "Create recipes from hundreds of websites by simply providing a URL"; AI import accepts "A URL: Mealie reads the page, or, for a video URL (e.g., YouTube or Instagram), transcribes the audio", images, and "Text: Paste a recipe as plain text, HTML, or JSON"; "Recipe HTML or JSON: Copy/paste structured HTML or JSON and Mealie can import it"; migrations from Tandoor, Nextcloud Cookbook, Paprika, Chowdown, Plan to Eat, Recipe Keeper, Copy Me That, My Recipe Box, Cook'n; community guides for "Bulk Url Import" and an "Import Bookmarklet". — [Mealie features docs](https://mealie.io/documentation/getting-started/features/)
- Tandoor: recipe-scrapers + its own `ingredient_parser`, automation rules (regex transforms on name/description/instructions), YouTube import via `pytubefix`. — [Tandoor importer](https://raw.githubusercontent.com/TandoorRecipes/recipes/develop/cookbook/helper/recipe_url_import.py)
- Paprika (Windows guide): a "built-in web browser"; "Press the Download button ... Paprika will attempt to clip the recipe from the page"; on failure "will display an error message"; manual mode: highlight text, click toolbar buttons `Name`, `Ingredients`, `Directions` etc. ("the current selection will be appended to the existing text"), right-click an image for "Add Photo to Recipe"; exported files "contain hrecipe or schema metadata"; a bookmarklet is mentioned. — [Paprika Windows user guide](https://www.paprikaapp.com/help/windows/)
- AnyList: iOS action extension, Android sharing activity, desktop extensions for Firefox, Chrome and Safari; "AnyList can import recipes from thousands of popular recipe websites"; 5 free web recipes, unlimited with AnyList Complete. — [AnyList help](https://help.anylist.com/articles/feature-overview-recipe-import/)
- Samsung Food (ex-Whisk): "Just choose 'Save recipe link' from the Samsung Food app and paste your recipe URL"; Chrome extension "to save any page to your Recipe Box in just one click"; "not every recipe site and blog has metadata that is compatible with Samsung Food" and a "recipe validator tool" is offered; image scanning limited to 3 free scans for Basic users. — [Samsung Food help](https://support.samsungfood.com/hc/en-us/articles/18756427379476-How-to-Save-Recipes-to-Your-Samsung-Food-Recipe-Box)
- Copy Me That: a bookmarklet you "Drag ... to your bookmarks toolbar" that runs on the current page ("Go to the webpage and click the button"), with a help section "Help! The button takes me back here!"; also a Chrome Web Store extension and mobile apps. — [Copy Me That button page](https://www.copymethat.com/info/button/); [Chrome Web Store](https://chromewebstore.google.com/detail/copy-me-that/lgjinjcobiflbbnhenlfkcjpeeacklfl)
- Plan to Eat: browser extensions for Chrome, Firefox and Safari plus iOS/Android share extensions; the former bookmarklet is retired; the extension opens "a side panel that doesn't cover up content in the current page" with an Import button. — [Plan to Eat Recipe Clipper](https://www.plantoeat.com/recipe-clipper/)
- Crouton (v2026.4, Sept 13): "supports importing recipes from almost everywhere! Pull recipes automatically out of websites"; "Import recipes using schema.org Recipe JSON or JSON-LD. Paste structured recipe data or import individual JSON files and ZIP archives"; photo/OCR/AI and PDF import; a review notes "you have to proofread". — [App Store: Crouton](https://apps.apple.com/us/app/crouton-recipe-manager/id1461650987)
- Saffron: paste a URL into the import form; "it's not always possible for Saffron to import from all websites"; fallback "copy/paste the information into the form or try another website". — [Saffron docs](https://www.mysaffronapp.com/docs/import-recipe/)
- Recipe Keeper (Windows): a 2023-06-14 report that "Recipe Keeper no longer imports website recipes. All website searches within this app produce 'This page cannot be found.'", still open as of 2025-07-08 with no root cause documented. — [Microsoft Q&A](https://learn.microsoft.com/en-us/answers/questions/4143321/recipe-keeper-no-longer-imports-website-recipes-al)
- RecipeSage's RecipeClipper runs inside a headless Chromium page (Puppeteer) or as a browser extension; CSS-selector matching first, then TensorFlow.js classification of ingredient/instruction blocks. — [GitHub RecipeClipper](https://github.com/julianpoy/RecipeClipper)
- Vendor claim: bulk imports "beyond 20 to 50 URLs per batch" hit source-site rate limits. — [recipe-manager.app blog (vendor)](https://www.recipe-manager.app/blog/import-recipes-allrecipes-nyt-bbc)

### Inferences
- Two architectures dominate: (1) server-side fetch + schema parse + LLM/OG fallback (Mealie is the reference implementation and is nearly identical to the user's planned design), and (2) client-side clipping in the user's browser session, which sidesteps paywalls/blocking and is why AnyList, Plan to Eat, Copy Me That and Paprika invest in extensions/share sheets.
- Every product exposes a manual escape hatch (highlight-to-field, paste text/HTML/JSON). Crouton's "paste schema.org Recipe JSON-LD" is a cheap, deterministic import surface worth copying.

### Gaps
- No public engineering write-ups from Paprika, AnyList, Samsung Food, Copy Me That, Saffron or Crouton describe their parsers (schema-first vs heuristics); only user-facing docs were found.
- Recipe Keeper's import mechanism (in-app browser vs server) is not documented publicly.

## KQ7. Heuristic fallbacks when there is no structured data

### Takeaway
Without JSON-LD/microdata, mature tools fall back to (a) OpenGraph for title/description/image, (b) plugin-specific DOM hooks and heading-walks for ingredients/steps, (c) Readability/Defuddle-style main-content extraction (Defuddle also surfaces `schemaOrgData`), and (d) in-browser selector/ML clipping (RecipeClipper); these fail on paywalled/truncated DOMs, JS-rendered pages and free-form prose recipes.

### Cited Findings
- OpenGraph fallback is standard: recipe-scrapers builds an OpenGraph object alongside the schema object and has `OpenGraphFillPlugin`/`OpenGraphImageFetchPlugin`; Mealie's final strategy reads `og:title/og:description/og:image/og:article:tag`. — [`_abstract.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_abstract.py); [Mealie `scraper_strategies.py`](https://raw.githubusercontent.com/mealie-recipes/mealie/mealie-next/mealie/services/scraper/scraper_strategies.py); every fixture in the corpus carried an `og:image` (48/48) — [recipe-scrapers test corpus](https://github.com/hhursev/recipe-scrapers/tree/main/tests/test_data)
- Plugin DOM hooks usable without JSON-LD: WPRM `wprm-recipe-name`, `wprm-recipe-ingredient` (+ `-amount`, `-unit`, `-name`, `-notes` spans), `wprm-recipe-ingredient-group`/`wprm-recipe-group-name`, `wprm-recipe-instruction-text`, `wprm-recipe-servings`, `wprm-recipe-time`, `wprm-recipe-image`; Tasty `tasty-recipes-title`, `tasty-recipes-ingredients-body`, `tasty-recipes-instructions-body`, `tasty-recipes-yield`, `tasty-recipes-prep-time`, `tasty-recipes-cook-time`, `tasty-recipes-total-time`, `tasty-recipes-notes`; step anchors `#wprm-recipe-{id}-step-{group}-{n}` and `#instruction-step-{n}`. — [natashaskitchen_2](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/natashaskitchen.com/natashaskitchen_2.testhtml); [cookieandkate_2](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/cookieandkate.com/cookieandkate_2.testhtml)
- Heading-walk grouping (headings + list items in DOM order, fuzzy-matched to known ingredient strings by bigram Dice similarity) is the library-standard way to recover sections. — [`_grouping_utils.py`](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/recipe_scrapers/_grouping_utils.py)
- RecipeClipper: "looking for common CSS selectors present on cooking sites, and grabbing the text within", then "uses machine learning to look at the content of the page and grab sections that it thinks are ingredients or instructions"; needs `innerText` (browser) for accuracy; in-browser ML "~30 seconds per page". — [GitHub RecipeClipper](https://github.com/julianpoy/RecipeClipper)
- Defuddle 0.19.4 (2026-09-17): "extracts the main content from web pages ... removing clutter like comments, sidebars, headers, footers"; vs Readability it "removes fewer uncertain elements", standardizes footnotes/math/code, uses mobile styles to drop elements, and "extracts richer metadata including schema.org data"; API `new Defuddle(document, options).parse()` on a DOM `Document` (browser `document`, or `defuddle/node` with linkedom, JSDOM or happy-dom); returns `content`, `contentMarkdown`, `title`, `description`, `author`, `published`, `domain`, `site`, `favicon`, `image`, `language`, `wordCount`, `parseTime`, `metaTags`, `schemaOrgData`; "very much a work in progress"; no explicit Workers claim. — [GitHub kepano/defuddle](https://github.com/kepano/defuddle); [registry](https://registry.npmjs.org/defuddle)
- `@mozilla/readability` 0.6.0 (2025-03-03, zero dependencies, 154 KB) needs a DOM implementation; `@postlight/parser` 2.2.3 was last published 2022-10-24 with heavy deps (`jquery, moment, cheerio, turndown, iconv-lite, ...`; 11.5 MB unpacked). — [registry readability](https://registry.npmjs.org/@mozilla%2Freadability); [registry postlight](https://registry.npmjs.org/@postlight%2Fparser)
- Paywall/truncation failure mode: NYT marks the recipe block `hasPart{cssSelector:".recipe", isAccessibleForFree:"False"}` and a vendor reports the unauthenticated DOM shows "only the first few ingredients". — [nytimes fixture](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/cooking.nytimes.com/nytimes.testhtml); [recipe-manager.app blog (vendor)](https://www.recipe-manager.app/blog/import-recipes-allrecipes-nyt-bbc)
- MealPlan's spec adds a JS-state fallback: search Next.js `__NEXT_DATA__` "for recipe-shaped objects" (BBC Good Food, NYT, tasty.co, Delish, Kitchn, Pioneer Woman fixtures are all Next.js pages). — [MealPlan issue #20](https://github.com/holgerkrupp/MealPlan/issues/20); [bbcgoodfood_1](https://raw.githubusercontent.com/hhursev/recipe-scrapers/main/tests/test_data/bbcgoodfood.com/bbcgoodfood_1.testhtml)

### Inferences
- A cheap deterministic ladder for a Worker: JSON-LD → microdata → plugin class hooks → OpenGraph + Readability/Defuddle text → LLM. Readability output is best treated as LLM input (clean prose), not as a source of fields, because ingredient/step boundaries are not recoverable from prose deterministically.
- Heading-keyword heuristics ("Ingredients"/"Instructions") will misfire on placeholder headings and on pages with multiple recipes; MealPlan's placeholder-rejection rule and completeness scoring are the minimal guards.

### Gaps
- No measured accuracy for Readability/Defuddle on recipe pages, and no source showing Defuddle running on Cloudflare Workers with linkedom (only `defuddle/node` is documented).
- Ingredient-line regex heuristics ("^\d+(\s\d/\d)?\s*(cup|tbsp|...)") were not found documented in any of the mature projects; they rely on parsers like `parse-ingredient`/`ingredient_parser` after extraction instead.
